# 图片内容审核链路调研（2026-11-23）

> 目标：给「视觉百花 Sakura Gallery」的 L0/L1/L2 三级发布 + Agent 审核链路做 buy-vs-build 选型。
> 标签约定：**[官方]** 厂商文档/定价页原话；**[本项目实测]** 来自 `AGENTS.md` §10 已踩过的坑；
> **[社区]** 第三方基准/实测；**[估算]** 由官方单价推算，未实测。价格若无特别说明为人民币含税目录价。

## 0. 结论先行

| 决策 | 方案 | 关键数字 | 理由 |
|---|---|---|---|
| **采用** | 规则前置：Pillow + pyexiftool + imagehash | 单张 pHash 约 5–15 ms，0 元 | 查重/EXIF/GPS/字体清单不花钱，先砍掉 60–70% 无需模型判断的样本 |
| **采用** | `qwen3-vl-plus` 单层快筛，输出结构化 JSON | 输入 1 元/百万 token、输出 10 元/百万 token；本项目实测 **1.9 s / 57 输出 token** | 单张约 0.0015–0.003 元（**2–3 元/千张**），且能直接产出 `suggested_tier`/`copyright_risk` 这类业务字段 |
| **采用** | `deepseek-v4.1-flash` 只跑 L2 与低置信度 | 本项目实测 **4.7 s / 590 输出 token**；`max_tokens` 必须 ≥2048 | 推理型模型，思维链计入 `max_tokens`，给少了可见输出会被吃光截断 |
| **不采用（主链路）** | 阿里云图片审核 2.0 / 腾讯云图片内容安全 | 腾讯 25 元/万张（**2.5 元/千张**）；阿里国际站 0.6–1.2 USD/千次（≈4.3–8.6 元/千张） | 比自建 VLM 贵 1–4 倍，且只能给通用违规标签，给不出平台自有的 tier/字体/作品类型判断 |
| **采用（兜底）** | 上架前对 `sensitive` 命中样本再调一次云审核 API | 2.5–4.3 元/千张，仅覆盖约 2–5% 样本 | 涉政/暴恐是自建 VLM 最不可靠、后果最严重的品类，用持牌审核兜底 |
| **不采用** | 开源 NSFW 模型（NudeNet / nsfw_model / CLIP 零样本）全量跑 | 模型 20–350 MB，CPU 30–200 ms/张 | 要维护第二套模型与阈值，误判率不可控，且完全没有涉政能力；收益被 VLM 覆盖 |
| **不采用** | AIGC 鉴别 API 全量跑 | 腾讯「图片 AI 生成识别」**0.1 元/张 = 100 元/千张** | 是普通审核的 40 倍价。AIGC 合规靠「强制声明 + 元数据核验」，鉴别只用于举报/争议样本 |

**一句话**：审核链路用「规则（免费）→ 1 个 VLM 快筛（约 2.5 元/千张）→ 推理模型只处理难例 → 人工终判」，
云厂商内容审核只做涉政兜底，AIGC 鉴别不铺量。

## 1. 规则前置：现成库与实测开销

| 用途 | 库 | 体积/依赖 | 备注 |
|---|---|---|---|
| EXIF / XMP / 格式嗅探 | **Pillow ≥10.2**（已在 `backend/requirements.txt`） | wheel ≈3 MB | `Image.open().verify()` 能挡掉伪造后缀；EXIF 用 `getexif()` 读 |
| EXIF/XMP/PNG tEXt 全量抽取 | **pyexiftool**（依赖 Perl `exiftool` 二进制） | exiftool ≈20 MB | 唯一可靠的 XMP/C2PA/隐式标识读取方式，见 §5；**建议加** |
| 感知哈希查重 | **imagehash**（aHash/dHash/pHash/whash） | 纯 Python + numpy，≈100 KB | pHash 8×8 DCT 对压缩/缩放稳健；64 bit → 存 `bigint`，汉明距离 ≤6 判重 |
| 重删/相似检索 | imagededup（CNN 版） | 拉 torch 数百 MB | **不用**：torch 是 AGENTS.md §11 明令禁止的必装依赖 |
| TLSH / 局部敏感哈希 | ppdeep（TLSH 的 Python 封装） | 小 | 可选，pHash 已够用 |

- 本机实测（12 核/16 GB 开发机，Python 3.10，`backend/.venv`）：
  `fastapi+uvicorn+sqlalchemy+asyncpg+boto3+PIL` 全部 import 后 **峰值 RSS 61 MB**。
- **[估算]** 1080p JPEG 解码 + pHash：约 5–15 ms/张（解码占大头）；1 万张/天只需 ~2.5 分钟 CPU。
- 规则层还该做：GPS 存在性（有 GPS → 剥离 + 打 `privacy` 标记）、AIGC 元数据探测
  （`Software`/`parameters`/`prompt`/`c2pa` 字段）、pptx `fontTable` 字体清单、文件类型与体积白名单。

## 2. 快筛 VLM：自建 vs 云内容审核（核心对比）

### 2.1 自建 `qwen3-vl-plus`（百炼直连）

- **[官方]** 定价（`help.aliyun.com/zh/model-studio/model-pricing`，2026-11 更新）：
  0<Token≤32K 档 **输入 1 元/百万 token、输出 10 元/百万 token**；32K–128K 档 1.5/15；128K–256K 档 3/30。
  新开通有 **100 万 token 免费额度**（90 天）。
- **[本项目实测]** 单张校园照片：**1.9 s 延迟、57 输出 token**（结构化 JSON 已够用）。
  输入侧按 28×28 patch 估算，1280×960 约 1.2–1.6K 图像 token。
- **[估算]** 单张成本 = 1500×1/1e6 + 57×10/1e6 ≈ **0.0021 元 → 2.1 元/千张**；
  若压到 640px 长边（约 400 token）可降到 **0.001 元/张**。
- 并发：百炼按账号 RPM/TPM 限流，额度以控制台为准（未实测）；本地侧用 3–5 并发即可跑满 2c4g。

### 2.2 云内容审核 API 定价（官方目录价）

| 厂商/服务 | 单价 | 折合每千张 | 免费额度 | 备注 |
|---|---|---|---|---|
| **腾讯云** 图片内容安全（按量） | 25 元/万张 | **2.5 元** | 3000 张 / 15 天 | 预付费套餐低至 10 元/万张（=1 元/千张），180 万张起 ≈22 元/万张 |
| 腾讯云 图片 AI 生成识别 | **0.1 元/张** | **100 元** | 无 | 单张计量、按日结算；比普通审核贵 40 倍 |
| **阿里云** 图片审核 2.0 · 通用基线（国际站） | 0.6 USD/千次 | ≈4.3 元 | — | 含 `baselineCheck_global` + `aigcDetector_global` |
| 阿里云 图片审核 2.0 · 大小模型融合（国际站） | 1.2 USD/千次 | ≈8.6 元 | — | `postImageCheckByVL_global`，默认 QPS **50**（非大模型版 100） |
| 阿里云 图片审核 2.0 · 大模型入华版（国际站） | 0.7 USD/千次 | ≈5.0 元 | — | `postImageCheckByVL_ec` |

- **[官方]** 阿里云按「服务(service)」计费，`费用 = 图片张数 × 调用服务数`；资源包抵扣系数 2（通用）/4（高级）。
  国内站按量单价与国际站不同，**以控制台账单为准**（本文未取到国内站页面，未实测）。
- **[官方]** 腾讯云/阿里云均需**实名认证账号 + 开通服务**；腾讯首次开通给 3000 张试用。
- **[未实测]** 同步接口延迟官方未给 SLA；按接口形态估计 100–500 ms，需上线前用 100 张样本压一次。

### 2.3 判定

1. **成本**：自建 VLM 2.1 元/千张 < 腾讯 2.5 < 阿里 4.3–8.6。量小时差异不大，
   但自建的价值不在便宜，而在**能一次输出业务字段**（`has_identifiable_person`、`copyright_risk`、
   `suggested_tier`），云审核只能给「色情/涉政/暴恐/广告」通用标签，省不掉第二次判断。
2. **能力边界**：涉政、暴恐、违禁、旗帜这类**持牌与词库型**风险，自建 VLM 会漏且理由不可审计，
   必须留给云审核做终判（L2 链路里先 VLM、命中 `sensitive` 再调云 API）。
3. **可用性**：单点依赖一个渠道有明显风险（AGENTS.md 记录过 NewAPI 代理 10 s 超时全 502）。
   快筛必须可降级：VLM 超时/5xx → 直接落人工队列并标记 `degraded`，不要卡住发布。

## 3. 难例复核：`deepseek-v4.1-flash` 用法与陷阱

- **[本项目实测]** 4.7 s / 590 输出 token；推理型模型。
- 陷阱：`max_tokens` 同时约束**思维链 + 可见答案**。给 512 时答案会被思维链吃掉，
  表现为"输出正常结束但 JSON 不完整"。**建议 `max_tokens ≥ 2048`，客户端超时 ≥30 s**。
- 用它做什么：只对「快筛判 L2」或「置信度低 / JSON 解析失败 / 敏感命中」的样本二次判定，
  输入 = 图片 + 快筛 JSON + 平台规则摘要；输出 = `final_tier / reason / cited_rules[]`。
- **[估算]** 单次 2K 输入 + 600 输出，按推理模型 1–4 元/百万 token 量级 ≈ **0.004–0.008 元/次**；
  若 L2 占比 5%，1 万张/月也只多 2–4 元。**贵不到哪去，但延迟 4.7 s 决定了它不能进同步链路**。

## 4. 人工队列 + 审计 + 成本护栏（可执行清单）

| 机制 | 做法 |
|---|---|
| 队列形态 | `works.status` + `review_tasks` 表（`stage`：rule/vlm/reason/human；`verdict`；`model`；`tokens_in/out`；`cost`；`latency_ms`；`degraded`）。**不要**只靠 `BackgroundTasks`（进程重启即丢） |
| 审计 | 每次模型调用落一行，保留 `prompt_hash` + 输出 JSON + 模型版本；人工终判写 `human_verdict`/`human_id`/`reason`，与 agent 意见同表可对比 |
| 成本护栏 | ① 日预算硬上限（例：5 元/天，超限自动降级为"仅规则 + 人工"）② 单用户上传配额（例 20 张/天）③ 按 tier 分流：仅 L2/低置信度进推理模型 ④ 连续 5 次超时或 5xx → 熔断 30 分钟 |
| 采样 | 对 L0 已放行样本按 1% 抽样回看，用于估计漏报率；每月复盘一次阈值 |
| 脱敏 | 送审前剥离 GPS、学号、真实姓名；日志里不写完整 EXIF |

**[估算]** 1000 张/月、L2 占 5% 的月度成本：
规则 0 元 + 快筛 2.5 元 + 复核 0.05 元 + 涉政兜底（3% × 2.5 元/千）≈ **2.6 元/月**。
量级上完全可以先跑起来再看账单，不需要预付费套餐。

## 5. AIGC 法定标识对审核链路的要求（《人工智能生成合成内容标识办法》，2025-09-01 施行）

**[官方]** 原文要点（网信办 2025-03-14 发布，国信办通字〔2025〕2 号）：

| 条款 | 要求 | 对本站的落地 |
|---|---|---|
| 第三条 | 标识分**显式**（用户可感知）与**隐式**（文件数据中，不易感知） | 前端角标 + 下载文件元数据，两套都要 |
| 第四条(三) | 图片应在**适当位置**添加显著提示标识 | 详情页/大图角落水印式角标 + `alt`/说明 |
| 第四条末款 | 提供**下载/复制/导出**时，文件必须含显式标识 | 下载接口出图时合成角标（或提供带角标版本） |
| 第五条 | 文件元数据中写**隐式标识**：生成合成属性信息、服务提供者名称或编码、内容编号 | 出图前写 XMP（`XMP-dc:Description` + 自定义 `SakuraAIGC:*`），用 exiftool 落盘 |
| 第六条 | 平台侧：核验元数据→有标识则提示；无标识但用户声明→提示"可能为生成合成"；无标识也未声明但检出痕迹→提示"疑似" | 三级文案：`AIGC 生成` / `可能为 AIGC` / `疑似 AIGC`，对应 `aigc_label` 三态 |
| 第六条末款 | 传播平台在元数据中追加平台名称/编码/内容编号 | 发布时再写一次 XMP（`label_written` 字段已预留） |
| 第九条 | 用户申请无显式标识版本时，需留存日志**不少于 6 个月** | 审核/发布日志保留 ≥180 天 |
| 第十条 | 用户须主动声明；禁止恶意删除/篡改标识 | 上传表单强制勾选 + 下载端不提供去标识选项 |
| 第十四条 | **2025-09-01 起施行** | 已在生效期内，属硬性合规项，不是"以后再说" |

- 配套强制性国标 **GB 45438-2025《网络安全技术 人工智能生成合成内容标识方法》** 同日实施，
  给出元数据字段与显式标识的具体样式；实现前应按该标准核对字段名（本文未逐条查证原文）。
- 审核链路的实际含义：**AIGC 判定 ≠ 只有模型检测**。链路优先序应为
  ① 用户声明（强制）→ ② 元数据/EXIF/XMP 探测（规则层，免费）→ ③ VLM `likely_aigc` 软判断
  → ④ 付费鉴别 API（仅争议/举报样本）。这与 §0 的"不铺量鉴别"一致。

## 6. 开源方案在小机器上的可行性（结论：不做）

| 方案 | 体积 | CPU 单张 | 结论 |
|---|---|---|---|
| NudeNet（ONNX 检测器） | 模型约 80 MB 级 | 社区报告 30–80 ms | 只能判裸露，误报需长期调阈值；无涉政能力 |
| GantMan/nsfw_model（Keras MobileNet） | 约 20–30 MB | 数十 ms | 同上，且要装 TensorFlow（重） |
| CLIP 零样本（ViT-B/32 ONNX 量化） | 90–350 MB | 100–200 ms | 语义自由度高但要自建提示词与阈值，维护成本 > 收益 |
| 2c4g 可行性 | 常驻 150–350 MB | — | 跑得动，但会与 PG/应用抢内存；**收益被 `qwen3-vl-plus` 覆盖** |

不采用的核心理由：**多一套模型 = 多一套阈值与回归测试**，而项目只有一个人维护；
VLM 已经能同时给 NSFW、肖像、版权风险与 tier 建议，一套链路更好审计。

## 7. 落地顺序（估计工作量）

1. **P0（1–2 天）**：规则层（Pillow 格式校验 + imagehash 查重 + GPS 剥离 + AIGC 字段探测）落 `review_tasks`。
2. **P0（1 天）**：`qwen3-vl-plus` 快筛，JSON schema 固定 6 字段，超时 20 s、重试 1 次、失败降级。
3. **P1（1 天）**：`deepseek-v4.1-flash` 复核，`max_tokens=2048`，只接 L2/低置信度。
4. **P1（0.5 天）**：成本护栏（日预算 + 配额 + 熔断）与审计字段。
5. **P2（按需）**：涉政兜底接腾讯云图片内容安全（2.5 元/千张），仅 `sensitive` 命中时调用。
6. **P0 合规**：三态 AIGC 文案 + 下载文件 XMP 写入（与审核链路解耦，可并行）。

## 8. 风险

- **R1｜渠道单点**：快筛只依赖百炼直连；代理渠道曾整体 502（AGENTS.md §10）。必须做可降级 + 人工兜底，不能阻塞发布。
- **R2｜漏报责任**：VLM 对涉政/暴恐漏报，平台仍要担责。兜底方案是 L2 强制人工 + 抽样云审核。
- **R3｜AIGC 元数据被删**：用户可在本地清 XMP。对策是服务端出图时二次写入（第六条末款），并保留声明记录。
- **R4｜token 计量错配**：思维链计入 `max_tokens` 与计费输出，推理模型的实际成本可能比"590 tokens"高数倍，必须按账单校一次。
